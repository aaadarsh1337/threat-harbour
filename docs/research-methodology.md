# Research Methodology

## Research Questions

- What unsolicited SSH activity reaches the sensor?
- Which usernames, passwords, commands, and services are most common?
- How does activity vary by UTC time period?
- Which behavioral categories can be identified from Cowrie events?
- What operational challenges arise on a Free Tier VM?

## Study Design

This is an observational study using one lightweight Cowrie sensor from `2026-08-27` through `ongoing` (interim cutoff `2026-09-06T20:36:00Z`).

No external systems are scanned or accessed.

## Collection Process

1. Cowrie writes structured JSON events.
2. Logs are copied into a controlled analysis directory.
3. Events are parsed and normalized.
4. Duplicate or malformed records are recorded and handled explicitly.
5. Aggregate metrics are generated.
6. Raw data is redacted before publication.

## Inclusion Criteria

Include events that:

- Were generated by the Cowrie sensor
- Have a valid UTC timestamp or documented timestamp correction
- Belong to the observation period
- Contain sufficient fields for the relevant metric

## Exclusion Criteria

Exclude:

- Local administrator test events
- Synthetic validation events
- Duplicate exports
- Records outside the observation period
- Data that cannot be safely published

## Reproducibility

Record:

- Cowrie version
- OS version
- OCI region and VM shape
- Configuration revision
- Collection timestamps
- Script versions
- Analysis commands
- Dataset hashes
- Redaction rules

## Ethics

The sensor is intentionally exposed for defensive observation. Analysis must avoid unnecessary publication of personal information, credentials, private keys, malware content, or sensitive infrastructure details.
